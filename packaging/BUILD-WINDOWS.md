> 最新构建状态：以批次 8 报告（materials/批次8-复审57条全修报告-2026-11-16.md）记录的 GitHub Actions run 为最新版；上一个已确认 run 为 43830434017（批次 7，commit 36c1293），批次 8 构建完成后即被取代。

本工程已在 Linux 环境完成全部搭建与配置校验，仅差最后一步「在 Windows 工具链上实际编译」。
两种构建方式任选其一，产物相同：`AI PM Coach_0.1.0_x64-setup.exe`（NSIS 安装包，已内嵌 WebView2 离线安装程序，目标机器无需联网、无需预装任何组件）。

## 方式 A：本机构建（预计 15–30 分钟，多为下载与编译等待）

前置：Windows 10 / 11，64 位。

### 1. 安装 Node.js

- 到 https://nodejs.org 下载 **LTS 版（18 或更高）** 安装包，默认选项装完。
- 重新打开一个 PowerShell 窗口，验证：`node -v` 能输出版本号。

### 2. 安装 Rust

- 打开 https://rustup.rs ，下载 `rustup-init.exe` 运行，全程默认选项（默认即 MSVC 工具链）。
- 重新打开 PowerShell，验证：`cargo --version` 能输出版本号。

### 3. 安装 Visual Studio 2022 生成工具（Build Tools）

- 到微软官网下载 **「Build Tools for Visual Studio 2022」（Visual Studio 2022 生成工具）**。
- 运行安装器，在「工作负荷」页勾选 **「使用 C++ 的桌面开发」**（含 MSVC 编译器与 Windows SDK，约数 GB），完成安装。

### 4. 构建

把本工程文件夹放到任意目录（路径不要带中文和空格更稳妥），在工程根目录打开 PowerShell：

```powershell
npm install
npx tauri build --target x86_64-pc-windows-msvc --bundles nsis
```

首次构建会联网下载依赖与 WebView2 离线安装程序并嵌入安装包，请保持网络畅通；之后再构建可断网。

### 5. 产物位置

```
src-tauri\target\x86_64-pc-windows-msvc\release\bundle\nsis\AI PM Coach_0.1.0_x64-setup.exe
```

## 方式 B：GitHub Actions 构建（本机零安装）

适合不想在本机装工具链的情况。本工程已自带 `.github/workflows/build-windows.yml`：

1. 把**本工程文件夹作为仓库根目录** push 到 GitHub（若要并入已有的 AI PM Coach 仓库，把本文件夹内容放在该仓库根目录，或单独建一个仓库放它）。
2. 在 GitHub 仓库的 **Actions** 页选择 `build-windows`，点 **Run workflow**（push 到 main 分支也会自动触发）。
3. 构建完成后，在该次运行记录底部的 **Artifacts** 里下载 `AI-PM-Coach-Windows`，解压即得安装包 exe。

GitHub 的 windows-latest 镜像自带 Visual Studio 2022 生成工具，工作流会自动装好 Rust 与 Node，无需你做任何本地配置。

## 构建成功后：真机确认清单（约 10 分钟）

1. 双击安装包完成安装；在另一台**没有 WebView2 的机器**（或虚拟机）上再装一次，确认 WebView2 被静默装上、程序能打开。
2. 首次启动：窗口标题为「AI PM Coach」，窗口尺寸正常、内容无错位。
3. 程序已打开时再次双击图标：应聚焦已有窗口，而不是开出第二个。
4. 完整冒烟一遍：开始测评 → 答完 18 题 → 看结果与诊断 → 进学习模式 → 打开错题本/面试演练 → 用数据管理导出一个 JSON。
5. 关掉程序再打开：刚才的测评记录和学习进度还在（exe 版数据存在本机，与浏览器里的数据不互通；迁移用应用内「导出/导入」JSON）。
6. 断网状态下重复第 4 步冒烟，全程应无任何联网提示或功能缺失。
7. 从系统设置卸载：快捷方式与程序文件被正常移除。

## 补充：异常场景真机清单（待真机验证，网页版已自动化实测对应项）

以下几项只能在 Windows 真机上验（网页版对应项 ABN-04..08 已在无头 Chromium 实测通过；exe 与网页版共用同一份前端与存储机制，预期行为一致）：

8. **答题中途用任务管理器结束进程**：开始测评答几题后，在任务管理器里结束「AI PM Coach」进程，再重新打开。预期：出现「未完成的测评，继续作答？」恢复卡，点继续能回到下一题、已答记录在。
9. **真断电/强制关机后重开**：使用中直接长按电源或拔电（笔记本可用强制关机模拟），开机后打开程序。预期：程序正常打开不白屏；已完成测评、快照、学习进度在。说明：浏览器内核（WebView2）的本地存储是异步提交的，断电瞬间最后几秒内刚写入的一小批数据有可能来不及落盘而丢失，这是所有同类软件共有的平台行为；重要数据可用应用内「数据管理 → 导出全部数据」导出 JSON 备份兜底。
10. **学习/演练中途强杀进程**：在学习页标记一个知识点已学、或在演练里自评一题后，用任务管理器结束进程再重开。预期：已学标记与自评记录还在（这两类在写入后随后续操作即被提交，网页版突关实测逐字保留）。

任何一步不符合预期，把现象（最好带截图）发回给 Muse，会按「先判定是外壳问题还是共享代码问题」处理：共享代码问题会同步修网页版并刷新已导出的网页版文件夹。

## 补充二：批次 5 新功能真机冒烟（收藏 / 学习笔记）

11. **答题收藏 → 收藏夹重做**：开始测评，在任意一题点「☆ 收藏」；答完后在结果页确认该题也显示「★ 已收藏」；回落地页打开「收藏夹」，确认该题在列表里，展开能看到选项、正确答案与解析，点「重做本题」答一次有即时对错提示；关掉程序重开，收藏还在。
12. **选区右键加笔记 → 笔记页编辑备注**：进学习模式打开任一知识点，选中一段文字点右键，应出现「加入学习笔记」菜单（无选区时右键应是原生菜单）；点击加入后打开「学习笔记」页，确认摘录在列表里，给它加一句备注保存；关掉程序重开，笔记与备注都还在。

## 补充三：批次 6 修复真机冒烟（批次 8 · 三-4 补入）

13. **学习计划空态（批次 6 修复 1）**：全新安装（或先在数据管理里清空全部数据）后打开「学习模式」，确认计划面板显示空态引导（提示先完成一次测评或点「编辑计划」），**不再出现**预填的「系统全学」假数据；点「编辑计划」能正常打开编辑器。
14. **只学最弱维待生效全链路（批次 6 修复 2）**：无测评成绩时在计划编辑器点选「只学最弱维」：应能点选并进入「待生效」状态（出现将在首次测评后按最弱维聚焦的说明）；完成首次测评后回学习页，确认计划已自动按最弱维聚焦（状态文案变为已生效并指明维度）；若此前已有自定义计划，点选时应先弹确认提示（首次测评后将替换自定义计划）。

## 补充四：批次 8 真机专属验证项（WebView2 / 安装器行为，网页版无法替代）

15. **选区笔记菜单在 WebView2 下的多路径（G-04）**：在知识点详情页选中一段文字：①右键应出现「加入学习笔记」自定义菜单（覆盖原生菜单）；②菜单出现后点页面空白处、按 Esc、滚动页面、切换视图——四种方式都应能关闭菜单；③在窗口边缘附近选区右键，菜单不应溢出窗口（应自动翻转位置）；④用浮动按钮「＋ 加入学习笔记」加入一条，再到结果页、错题本各选一段加入，确认三条都进了「学习笔记」页且来源标注正确（知识点 / 测评结果 · 弱点诊断 / 错题本）；⑤答题进行中页选中文字，确认**不**出现浮动按钮、右键为原生菜单（不干扰作答）。
16. **安装失败指引可读（G-11a）**：如有条件，在一台权限受限或磁盘空间不足的机器上运行安装包，确认失败提示能看懂、且 README 中「系统要求与依赖」一节写明的 Microsoft Edge WebView2 Runtime 名称与获取方式与提示一致；无条件时至少通读 README 该节，确认名称、下载入口描述无误。
17. **覆盖安装后旧数据存续（G-11b）**：先装旧版并做一轮测评、加几条笔记，再直接安装新版（不卸载），打开后确认测评记录、笔记、收藏都还在（覆盖安装不清空应用数据）。
18. **单实例二次拉起（G-11c）**：程序已打开时，从桌面快捷方式、开始菜单、安装目录 exe 三处各再启动一次，确认每次都是聚焦已有窗口、不新开第二个窗口，且已有窗口中的作答/浏览状态不被打断。
