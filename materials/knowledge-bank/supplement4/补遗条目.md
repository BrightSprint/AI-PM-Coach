# 一、技术术语篇（补遗三期）

### **分类评测指标（准确率 / 精确率 / 召回率 / F1）：**

分类评测指标衡量分类模型答得对不对，基础是混淆矩阵：按实际为正或负、预测为正或负交叉成四格，得到真正例、假正例、真负例与假负例。准确率是全部样本中预测正确的比例；精确率又叫查准率，是预测为正里真正为正的比例；召回率又叫查全率，是实际为正里被找回的比例。F1是精确率与召回率的调和平均，任一方偏低都会被明显拉低，不像算术平均能被高的一方掩盖，因此能逼着查准与查全同时达标。PM按误判代价取舍：拒答、风控等误报代价高的场景偏重精确率，问答覆盖等漏答代价高的场景偏重召回率，并结合小像这类制度问答定性判断哪边更伤信任。注意事项：类别极不平衡时准确率会骗人，负类占绝大多数时全猜负类也能有高准确率却找回不了正例，必须同时看精确率、召回率、F1与混淆矩阵。

### **AUC 与 ROC 曲线：**

ROC曲线把模型分数从高到低逐档设为阈值，每档得到一对真正率与假正率，连点成线，用来观察阈值变化时找回与误报的此消彼长。真正率是实际为正中被判为正的比例，假正率是实际为负中被误判为正的比例；曲线越向左上方凸起，模型在少误报时找回正例的能力越强。AUC是ROC曲线下的面积，衡量与阈值无关的排序能力：随机抽一正一负两个样本，模型给正样本分数更高的可能性越大，AUC越高。PM在模型选型与版本对比时可用AUC横向比较：同一评测集与口径下，AUC更高者排序能力更强，可作入围依据，但上线阈值仍须在业务样本上单独选定。注意事项：AUC高不等于当前阈值下体验好，阈值不当照样误报或漏报；类别极不平衡时还要结合PR曲线看，避免整体排序掩盖少数类的表现。

### **经典深度学习架构（CNN / RNN / LSTM / GAN / BERT）：**

CNN卷积神经网络擅长提取局部特征，是图像识别的经典架构；RNN循环神经网络按序处理序列、靠隐藏状态传递信息，但长序列下记忆会衰减。LSTM用门控机制决定信息的写入、保留与遗忘，缓解了RNN的长程依赖问题；GAN让生成器与判别器互相博弈，学习生成新样本。BERT基于Transformer编码器做双向预训练，擅长理解与分类；GPT基于解码器逐词生成，两者同属预训练谱系，分属理解与生成两条路线。PM在面试与方案评审中可用这条谱系识别老系统与基线模型：先判断存量系统用的是哪类架构、解决哪类问题，再讨论是否值得迁移到大模型方案。注意事项：不要把BERT这类编码模型与生成式大模型混为一谈，前者做理解与判别、本身不续写长文本；任务简单或成本受限时，经典架构仍可作基线。

### **容器化与模型部署格式（Docker / Kubernetes / ONNX）：**

Docker把代码、依赖与运行配置打成镜像、再以容器隔离运行，解决开发、测试与生产的环境一致性问题，是容器化的基础工具。Kubernetes是容器编排平台，负责大量容器的调度、发布与运维，能按负载弹性伸缩，并在故障时自动恢复，适合规模化在线服务。ONNX是跨框架的模型交换格式，模型导出为ONNX后可交给不同运行时在服务器或端侧执行，减少对原始训练框架的绑定。PM做私有化交付或端侧部署时要确认：交付物是镜像还是模型文件、目标环境能否运行对应容器与运行时、升级回滚由谁负责，并写进交付清单。注意事项：容器化只解决环境与运维，不等于模型被优化，速度与资源占用仍要实测；ONNX转换可能有算子不支持，转换后须用同批样本回归比对。
