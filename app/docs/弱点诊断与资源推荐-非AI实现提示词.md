# 弱点诊断 + 学习资源推荐 —— 非 AI 实现提示词（改写版）

> 改写原则：原提示词中所有"调用大模型生成"一律改为"本地规则引擎 + 预写内容库"。
> 运行时零 LLM、零网络请求（搜索按钮除外，见功能 2 说明）；所有文案在内容生产阶段写好、随应用打包。
> 凡原需求无法用规则完全等价实现之处，文末单列，不假装等价。

---

## 功能 1：弱点诊断（规则引擎版）

（与原版一致，不改）
用户答完测评、看到雷达图的同时，每个维度有一段针对他个人的诊断，让他清楚四件事 + 一段鼓励：
1. 一句话总结该维度水平：30 字以内，犀利不圆滑（例："你对大模型选型缺乏判断框架"，禁止"你在 AI 基础上还有提升空间"这类套话）。
2. 具体问题：必须引用他实际答错的题（测评序号、子考点、题干摘要）。
3. 为什么会错：必须基于答错题的证据推断，不许凭空猜。
4. 下一步动作：具体、立刻能开始，禁止"建议多学习"。
5. 鼓励：必须引用他答对的具体题目，不许空泛。


全部由本地诊断引擎（纯代码）按下列规则拼装，输入与原版相同：维度名、CAT 维度得分、该维全部答题记录（序号、题库 id、子考点、考核点、难度、所选答案、对错、用时）。

- **薄弱点区块 = 每道答错题一个区块**（CAT 每维 2-3 题，答错数天然 ≤3，正好落在原规格"1-3 个薄弱点"内）：
- 标题 = 该题子考点（sub_topic）；
- 证据框 = "在第 X 题" + 题干摘要（截断 40 字）；
- 错因 = 该题"你所选选项的干扰项解析"（题库 distractor_analysis 中所选字母的条目，逐字引用，它本身就写明了这个选项错在哪）+ 该题"难点"（difficulty_points）摘录；再叠加模式规则补充一句：答错的是低难度题 → "这是基础概念题，说明概念本身还没立住"；答错且用时 <15 秒 → "作答很快，更像是概念未成形时的直觉选择"；答错高难度题 → "这道题难在多因素权衡，错在取舍顺序"。
- **一句话总结**：模板句库按「维度 × 主要薄弱子考点 × 分数段」拼装，句式如"你在{子考点}上还没有形成判断框架""你对{子考点}的判断停留在概念层"。每个维度预写 ≥6 条句式，运行时按实际错题数据填空。
- **下一步动作**：动作库按维度预写，并与错题子考点挂钩，动作只允许三类可立即执行的：①去学习模式学某个具体知识点（给出知识点名，可点击直达）；②重做本维度同子考点的题（题库现题）；③读资源库中某一份具体资源（与功能 2 共用资源库，给出标题）。禁止出现"多学习、多了解"类空动作。
- **鼓励**：规则选取该维答对题中难度最高的一道，模板："你在第 X 题（难度 N）答对了『{子考点}』，说明{该题考核点第一项}你已经有判断力。"无答对题时改用全卷答对的最高难度题；全卷无答对题则显示预写的保底鼓励（不引用题目，并注明是保底文案逻辑，不伪造引用）。
- **死规矩（与原版对应，改为代码校验）**：总结句黑名单词表（"有潜力""提升空间""多学习"等）命中即替换为备用句；下一步动作必须命中动作库三类之一才允许显示；错因必须引用所选干扰项解析原文，不许引擎自创原因；鼓励必须带真实答对题序号，取不到就走保底分支。


没有网络调用，不存在调用失败。改为按数据充足度分三层，逻辑等价于原降级设计：
- L1 个性化诊断：该维有答错题可引用 → 完整四件事 + 鼓励；
- L2 基础诊断：该维全答对但分数 <90，或错题证据不足以成段 → 使用预写的「维度 × 分数段」通用诊断文本（6 维 × 4 段 = 24 段，分数段 0-40 / 40-60 / 60-80 / 80-100，内容生产阶段写好打包），卡片右上角小字标"（基础诊断）"，与原降级标注要求一致；
- L3 数据不足：该维答题数 ≤1 → 显示"这个维度的答题数据不足以生成诊断，建议你做一次专项测评。"（注：本产品 CAT 每维保底 2 题，L3 实际只会在异常中断时出现；原提示词写的"1-2 题"阈值若照搬，2 题的三个维度将永远无诊断，故阈值改为 ≤1，此为本次改写的一处口径调整，已报备。）
- 分数 >90：不出薄弱点区块，改为"已掌握 + 进阶挑战"：列出该维未考到的高难度子考点与学习模式进阶知识点。

（与原版一致）
结果页雷达图下方，每维一张诊断卡片：顶部维度名（加粗）+ 分数（大字号；<60 橙色、60-80 主色、>80 绿色）；其下一句话总结（大字号、主色）；再下 1-3 个薄弱点区块（子考点标题加粗 / 浅灰证据框 / 错因段落 / "→"开头主色加粗的下一步）；卡片底部绿色细边框的鼓励语；基础诊断时右上角极小浅色字"（基础诊断）"。


本地计算为毫秒级，不需要、也不伪造 loading 等待。进结果页默认展开最弱维度（用户最关心），其余 5 张折叠，点"展开查看诊断"即时展开（点击时才在本地组装该维诊断，行为与原版一致，只是没有网络等待）。原版"AI 正在为你生成针对性诊断（约 3 秒）"的文案删除——不许假装在调用 AI。

## 功能 2：学习资源推荐（规则匹配版）

（与原版一致）诊断卡片的"建议下一步"旁加"查看推荐资源"按钮，点击展开资源列表，每维 3-5 条。

产品内任何环节不输出 URL、不生成资源信息。资源来自**预制资源库**：内容生产阶段人工精选、逐条核验后写死在应用里，字段与原版相同：标题（具体到可搜到）、来源平台、类型（文章/视频/书/课程）、预计时长（分钟）、推荐理由（一句话，针对弱点写）、搜索关键词（3-6 个词）。选源标准沿用原版：知名作者（Andrew Ng、Karpathy、Chip Huyen 等）、大公司官方文档（OpenAI、Anthropic、Google AI、Hugging Face）、经典书籍；不收知乎/掘金/CSDN 具体文章、不收不知名博主、不收"最新文章"。


每条资源打标签：所属维度 + 若干主题标签（如 RAG、评测、Token 成本、提示词、Agent、安全合规…）。
展开某维推荐时：①先用该维答错题的子考点/题干/关键词文本与资源标签做包含匹配，命中的按命中数排序；②不足 3 条时用该维的通用资源补齐到 3-5 条；③推荐理由优先用资源库中针对该维预写的理由，命中具体薄弱点时在理由前拼上"针对你在{子考点}上的错题"。
匹配与排序全是本地字符串与计数逻辑。

（与原版一致）
资源列表每条一行卡片：标题（粗体）+ 类型徽章；第二行"来源平台 · 预计时长"；中间推荐理由（浅色）；底部按钮"用这个关键词搜索 →"，按钮上预览关键词，点击在新标签页打开 https://www.google.com/search?q={关键词}。
离线说明（新增）：最终 Windows 单机版脱网时该按钮无法打开搜索页，届时按钮降级为"复制搜索关键词"，此降级在打包版实现，本版（网页版）按原设计执行。

##
1. "推测为什么会错"：规则版只能基于证据（所选干扰项解析、难点、难度、用时模式）做归因，覆盖绝大多数情况，但无法像 LLM 那样对任意错题组合做开放式联想推断。文案中因此统一表述为基于答错题的推断，不用"AI 推测"字样。
2. 文案多样性：一句话总结与鼓励由模板填空，同维度多次测评可能看到相同句式；已用"每维 ≥6 条句式轮换"缓解，但不如生成式文案多变。
3. 资源库是有限精选（首版每维 3-6 条），新资源需随版本更新内容库，不能动态发现。
以上三点是"不用 AI"的固有代价，不存在"不用 AI 就完全做不出"的功能项；若产品方认为某一点不可接受，需另行裁决，不在本提示词执行范围内擅自接 AI。
