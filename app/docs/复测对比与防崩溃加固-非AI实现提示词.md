# 复测对比 + 防崩溃加固 —— 非 AI 实现提示词（改写版）

> 改写原则同上版：原稿凡涉及 LLM 的条款，要么因产品本无 LLM 而「不适用（已由架构消除）」，
> 要么改写为本地规则等价实现。运行时零 LLM、零网络（Google 搜索按钮除外）。

## 功能 1：复测对比（原稿本就无 AI，照规格实现）
- 能力快照：每次完成完整测评（≥10 题）后存一条快照 {日期、六维 CAT 分、总分、答题数、答对数} 到 localStorage，按时间累积；与已有 attempts 记录分开存（键 aipm.snapshots.v1），同一次完成只生成一条。
- 主页（落地页）「我的测评」区按快照数分三态：
- 0 个：不显示该区（或只显示雷达空状态 + 开始测评按钮，见加固 1-4）；
- 1 个：当前雷达图 + 提示「完成下一次测评后，你可以看到自己的进步对比。」+「立即复测」按钮；
- ≥2 个：对比雷达图（最近一次主色实线 + 0.3 半透明填充；上一次浅灰虚线无填充；边线粗细与标签字号一致）+ 三个关键数字（总分变化「上次 X → 本次 Y（±N）」、提升最大维度、仍需加强维度＝本次最弱维，文案含退步/停滞判断）；提升绿色、下降橙色、不用红色、无跳动动画；
- ≥3 个：「查看完整成长曲线」入口 → 时间轴视图：每个快照一个节点，展示总分趋势与六维各自得分随时间变化。
- 「立即复测」按钮（主页右上角/我的测评区）：按距上次测评天数三态——<3 天弱化 + 小字「建议再过几天复测，让学习有时间发挥作用。」；3-7 天正常 +「距离上次测评 X 天，来复测一次看看进步。」；>14 天高亮 +「已经 X 天没测评了，回来看看自己的水平吧。」（7-14 天按 3-7 天的正常态处理，小字同式。）
- 复测抽题过滤：CAT 引擎选词时优先从未答过的题里抽（跨全部历史 attempts 的题 id 集合）；某维某难度档未答题不足时先在该维内跨难度找未答题，再放开用旧题；过滤与放开都要在 [CAT] 日志里标明（如 reused=true）。
- 复测反馈（结果页顶部，仅当存在上一次快照时）：总分 +≥10 → 庆祝卡（主色底白字「你在 X 天里提升了 Y 分！」，无动画）；某维 +≥15 → 单维突破卡「你的维度突破了！」；总分下降 ≥6 → 橙色建设性卡 + 「查看本次错题」入口（展开本次答错题列表：题干、你的答案、正确答案、所选干扰项解析）；变化 -5..+5 → 温和卡「本次表现稳定。建议针对做专项练习，下次会有突破。」（+6..+9 的空档用温和正向卡，同式但肯定进步——原稿未覆盖此区间，改写版补齐并报备。）

## 功能 2：防崩溃加固（按组改写）

### 第一组（核心 edge case）
1. ~~LLM API 失败重试~~ → **不适用**：产品无任何 API 调用，此故障类已由架构消除。等价韧性要求：本地组装（诊断/推荐）若数据异常，走基础诊断托底，结果页永不出现空白/报错页（已有分层逻辑，纳入自测）。
2. 题库就绪检查：启动测评前校验题库，任一维度题目 <3 道 → 禁止启动并提示「题库未就绪，请联系管理员」。
3. 中途关闭恢复：每答一题立刻把进行中状态（引擎状态、已答记录、当前题、开始时间）写入 localStorage（键 aipm.inprogress.v1）；重新打开时若有未完成测评，落地页/测评入口处显示明显卡片「你有一次未完成的测评，继续作答？」+「继续」「放弃重来」两按钮；正常完成或放弃后清除该键。
4. 雷达图无数据：无快照时主页不画空雷达，显示空状态「完成测评后查看你的能力雷达图」+「开始测评」引导按钮。
5. ~~情景题超长输入~~ → **不适用**：当前产品没有开放式情景题、没有任何自由文本作答入口（测评与练习均为选择题）。此条留待将来真有文本作答功能时再启用（2000 字上限/1800 字提示/强制截断）。
6. ~~情景题极短/空白拦截~~ → **不适用**，理由同 5（<20 字提示与禁止提交规则随文本作答功能一并启用）。注：学习模式的题目粘贴框不是作答，不套用此规则。
7. 重复点击防护：凡触发状态推进的按钮（下一题、开始、提交类）在处理瞬间禁用并防抖，连点不重复推进、不重复写记录。
8. 维度题量不足与诊断：诊断卡片在该维答题数 1-2 题时显示「答题数据不足，无法生成针对性诊断」。【裁决已定】此条曾因 CAT 每维保底 2-3 题、按 1-2 执行会使三个 2 题维度永远无诊断而报请裁决；Suzuki 于 2026-11-13 明确裁决「严格 1~2 题」，按原稿执行，2 题维度只显示数据不足、不出诊断。

### 第二组（原「AI 失控响应」→ 改写为「评分透明与可申诉」）
1. ~~情景题评分依据~~ → **不适用**：无开放式评分。等价透明度由本组第 4 条（分数构成 modal）承担。
2. 申诉机制（保留，文案去 AI 化）：结果页分数区下方小按钮「我觉得评分不准」→ 弹出文本框填理由 → 写入 localStorage（键 aipm.appeals.v1，含时间、总分、六维分、理由）→ 小字提示改为「你的反馈会用于改进评分规则」（产品无评分模型，不许写「评分模型」）。
3. 诊断引用校验（原「prompt 死规矩」改写为代码断言）：个性化诊断组装完成后程序自检——卡片文本必须含至少 1 个真实题序引用；不满足则自动改走基础诊断并在控制台输出警告（等价于原稿「前端警告 + 重新生成」，本地版是即时重组装，不发请求）。
4. 能力分数可解释：点击雷达图/维度列表中的维度分数 → modal 显示该维构成：答了 X 题（其中高难度 4-5 级 Y 题）、答对 Z、答错 W，并逐题列出分数演进（初始 50 → 每题 旧分×0.7+贡献×0.3 → 当前分），公式必须与 CAT 引擎实际公式一致（原稿示例里的「基础分 50 × 0.5 + 本次贡献 × 0.5」与本产品公式不符，改写版以实际公式为准）；modal 内提供「重测这个维度」按钮 → 进入该维专项测评（5 题、维度内 CAT 难度自适应），专项结果单独展示、不生成完整快照、不覆盖主结果。

### 第三组（主动规避审计）
逐项检查当前产品并以代码/文案扫描佐证：无「连续打卡天数」、无「积分商城」、无「PK 排行榜」、无「每天必须来」式强制激励（含文案扫描：打卡/积分/排行/签到等词）。若发现任何一项，删除并在交付报告中列明删了什么；没有则明确报告「未发现，无删除」。

## 测试要求
交付时附《自测清单》一份：覆盖以上全部条款（含不适用项的核查方法），每项写明测试步骤与预期结果。
